# 一、產品定位與整體架構

## 1.1 產品定位

「碼上學｜CODE TO KNOW」是一個以 AI 為輔助的智慧學習與教育科技平台，整合課程教材、知識學習、題庫練習、模擬測驗、實作任務、學習分析及教師管理功能。

平台的核心理念：

**AI 協助學習，但不取代思考；讓每個人都能持續探索知識、理解問題並實際應用。**

平台不只服務資訊相關科目，未來也將逐步擴展至不同學科、職業教育及一般知識學習。

## 1.2 入口架構

採用「品牌入口＋角色登入」模式。

使用者先進入公開品牌網站，了解平台特色及學習服務，再透過登入系統進入相應的使用者平台。

主要角色：

1. 學生：課程、教材、練習、測驗、AI 助手及學習分析。
2. 教師：班級、課程、題庫、考試、成績及公告管理。
3. 管理員：使用者、權限、內容、系統及安全管理。

# 三、核心功能需求

## 3.1 會員與登入系統

**優先級：P0｜第一版**

| ID | 功能 | 需求 |
| --- | --- | --- |
| AUTH-001 | 註冊 | Email、密碼及必要資料 |
| AUTH-002 | 登入 | 帳號密碼驗證 |
| AUTH-003 | Google 登入 | 使用 Google Identity Services |
| AUTH-004 | 忘記密碼 | 安全的密碼重設流程 |
| AUTH-005 | 登出 | 清除有效登入狀態 |
| AUTH-006 | 角色驗證 | 學生、教師及管理員 |
| AUTH-007 | 權限控制 | 依角色及資源授權 |
| AUTH-008 | 帳號狀態 | 啟用、停用及待審核 |

安全要求：

- 密碼使用安全雜湊演算法保存。
- 使用安全 Cookie 或等效的安全憑證機制。
- 重要操作需重新驗證或二次確認。
- 後端每次請求都必須驗證權限。
- Google 登入必須由伺服器端驗證憑證。
- 不得將密碼、Token 或 API Key 寫入前端程式碼。

## 3.2 課程與教材系統

**優先級：P0｜第一版**

課程資料層級：

```text
科目
 └── 課程
      └── 單元
           └── 教學內容
                ├── 文字教材
                ├── 圖片
                ├── PDF
                ├── 影片連結
                ├── 練習題
                └── 實作任務
```

需求：

- 支援多科目及多單元。
- 教材可以新增、修改及下架。
- 課程可設定公開、私人或班級限定。
- 支援 PDF 與圖片教材。
- 影片採合法授權來源或外部嵌入。
- 記錄學生教材閱讀及完成狀態。
- 教材檔案須有權限檢查及容量限制。

## 3.3 題庫系統

**優先級：P0｜第一版**

第一版題型：

1. 單選題。
2. 多選題。
3. 是非題。
4. 填充題。

第二階段：

1. 配合題。
2. 程式或網頁實作題。
3. 圖片判讀題。
4. 操作任務題。

每題資料應包含：

- 題目 ID。
- 科目及單元。
- 題目內容。
- 題型。
- 選項。
- 正確答案。
- 解釋與解析。
- 難度。
- 知識標籤。
- 來源及授權資訊。
- 建立者及更新時間。

題庫需支援搜尋、分類、標籤、匯入、匯出及版本管理。

## 3.4 練習與測驗系統

**優先級：P0｜第一版**

練習模式：

- 自由練習。
- 依單元練習。
- 依難度練習。
- 錯題再練習。

測驗模式：

- 設定考試開始及結束時間。
- 設定作答時間。
- 設定題數及配分。
- 支援隨機出題及選項排序。
- 自動儲存作答進度。
- 提交答案並計算成績。
- 顯示測驗結果。
- 保存作答紀錄。

考試系統必須處理逾時、斷線、重複提交及伺服器時間差等情況。

## 3.5 AI 學習助手

**優先級：P0｜第一版**

AI 主要工作不是直接替學生完成所有題目，而是協助理解。

採用四階段提示：

| 階段 | AI 行為 |
| --- | --- |
| 第一階段 | 提醒相關觀念 |
| 第二階段 | 提供思考方向 |
| 第三階段 | 提供部分步驟及提示 |
| 第四階段 | 在適當情況下提供完整解析 |

AI 必須：

- 依據題目、教材及可用知識來源回答。
- 優先解釋觀念與錯誤原因。
- 不確定時明確表示不確定。
- 避免捏造教材內容或標準答案。
- 不得將學生個人資料送往未授權服務。
- 記錄必要的使用量、錯誤及延遲資訊。
- 具備 API 失敗、逾時及額度不足處理。

AI 模型、API 供應商及費用，留待第 8 階段確認。

## 3.6 學習分析系統

**優先級：P0｜基礎版**

學生分析：

- 總練習次數。
- 答題正確率。
- 平均作答時間。
- 各單元表現。
- 錯題分布。
- 學習完成進度。

教師分析：

- 班級整體正確率。
- 學生個別表現。
- 各單元錯誤比例。
- 作答時間分布。
- 學生學習進度。

分析結果必須根據實際作答紀錄計算，不可使用虛構數據。

## 3.7 遊戲與成就系統

**優先級：P1｜第二階段**

預計規劃 3–5 款教育小遊戲。

設計原則：

- 每款遊戲必須有明確學習目標。
- 開始前顯示遊戲規則。
- 遊戲結果與知識理解有關。
- 積分由後端驗證。
- 防止重複領取或修改分數。
- 遊戲紀錄可供學生查看。

## 3.8 教師管理與考試系統

**優先級：P1｜完整強化**

教師可：

- 建立班級。
- 邀請學生加入。
- 設定考試時間。
- 建立與管理試卷。
- 設定及格分數。
- 設定補考資格。
- 發布班級公告。
- 查看成績與學習分析。

考試中的隨機化、補考及學生排除規則，必須由伺服器端保存並執行。

# 七、安全、隱私及可靠性需求

## 7.1 資訊安全

- 密碼雜湊及安全登入。
- 伺服器端角色與資源權限檢查。
- 輸入驗證及輸出編碼。
- 防範 SQL Injection、XSS、CSRF 等常見風險。
- 登入與 API 速率限制。
- 檔案上傳類型、大小與內容檢查。
- API Key 僅存在安全的伺服器環境。
- 敏感操作保留稽核紀錄。

## 7.2 個人資料

- 蒐集資料前說明用途。
- 提供隱私權政策及服務條款。
- 不公開學生個人學習紀錄。
- 教師只能查看獲授權班級的資料。
- 提供帳號資料查詢及必要的刪除流程。
- 依適用的個人資料保護法規處理。

## 7.3 系統可靠性

- 定期資料庫備份。
- 重要操作具備錯誤復原機制。
- AI API 失敗時仍可使用非 AI 核心功能。
- 測驗提交需要防止重複寫入。
- 伺服器及錯誤紀錄需可供管理員追蹤。
