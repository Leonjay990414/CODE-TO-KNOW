## 一、設計目標

管理者後台是平台管理及維護的核心工作空間。

主要目標：

1. 管理平台使用者及帳號狀態。
2. 管理學生、教師及管理者角色權限。
3. 管理學校、班級及組織資料。
4. 管理課程及教材內容。
5. 管理題庫及題目分類。
6. 管理平台公告及通知。
7. 查看平台運作狀態。
8. 檢視系統操作及安全紀錄。
9. 管理 AI 服務設定及使用量。
10. 維護資料品質及平台安全。

設計原則：

- 管理資訊必須清楚且可追蹤。
- 高風險操作必須有確認機制。
- 權限遵守最小必要原則。
- 所有重要管理行為都應留下紀錄。
- 不將尚未整合的服務顯示為已啟用。
- 管理者權限不能由前端自行指定。

## 二、管理者導覽架構

### 2.1 側邊導覽

主要功能：

1. 管理首頁
2. 使用者管理
3. 角色與權限
4. 學校與組織管理
5. 班級管理
6. 課程管理
7. 教材管理
8. 題庫管理
9. 公告與通知
10. AI 服務管理
11. 平台數據
12. 系統監控
13. 安全與操作紀錄
14. 系統設定

實際顯示項目必須依管理者權限決定。

### 2.2 上方工具列

包含：

- 頁面標題。
- 全站管理搜尋。
- 系統通知。
- 管理者帳號。
- 登出入口。

重要管理功能不得只藏在不明顯的下拉選單中。

## 三、管理者首頁 Dashboard

### 3.1 首頁目的

讓管理者快速了解平台整體運作情況，以及目前需要處理的管理事項。

### 3.2 平台摘要

依照真實資料顯示：

- 使用者總數。
- 學生帳號數。
- 教師帳號數。
- 已建立課程數。
- 題庫題目數。
- 活躍班級數。
- 平台近期活動。

所有統計都必須標示統計時間或資料更新時間。

### 3.3 待處理事項

例如：

- 待審核教師帳號。
- 待審核課程。
- 待處理檢舉或問題。
- 系統錯誤通知。
- AI 服務異常。
- 資料匯入失敗。

### 3.4 系統狀態摘要

顯示：

- 前端服務狀態。
- 後端 API 狀態。
- 資料庫連線狀態。
- AI 服務連線狀態。
- 郵件服務狀態。
- 檔案儲存服務狀態。

若未完成整合，應顯示「尚未設定」或「未啟用」，不得以綠色正常狀態代替。

## 四、使用者管理

### 4.1 使用者列表

欄位：

- 使用者識別碼。
- 顯示名稱。
- 電子郵件。
- 使用者角色。
- 帳號狀態。
- 建立日期。
- 最近登入時間。

提供：

- 搜尋。
- 角色篩選。
- 帳號狀態篩選。
- 建立日期篩選。
- 分頁。

### 4.2 使用者詳細頁

顯示：

- 基本帳號資料。
- 角色及權限。
- 所屬組織。
- 所屬班級。
- 帳號狀態。
- 必要的操作紀錄。

敏感資訊不得直接顯示，例如密碼雜湊、登入憑證及 Token。

### 4.3 帳號管理操作

依權限提供：

- 啟用帳號。
- 停用帳號。
- 鎖定帳號。
- 解除鎖定。
- 重設帳號驗證狀態。
- 檢視帳號紀錄。

涉及帳號停用或鎖定時，必須要求管理者確認並填寫原因。

### 4.4 帳號審核

教師或其他特殊角色申請可進入審核流程。

顯示：

- 申請人資訊。
- 申請角色。
- 申請時間。
- 必要的驗證資料。
- 審核狀態。

管理者可核准或退回申請，並留下審核紀錄。

## 五、角色與權限管理

### 5.1 角色分類

平台基本角色：

- 訪客。
- 學生。
- 教師。
- 管理者。

未來可依組織需求擴充角色，但不得直接混用角色名稱與實際權限。

### 5.2 權限設定

權限可依以下資源分類：

- 使用者。
- 組織。
- 班級。
- 課程。
- 教材。
- 題庫。
- 測驗。
- 公告。
- AI 服務。
- 系統設定。

### 5.3 權限操作

提供：

- 查看角色權限。
- 編輯權限配置。
- 指派角色。
- 撤銷角色。
- 檢視權限變更紀錄。

重要權限變更應要求再次確認，並記錄操作者、時間、對象及變更內容。

### 5.4 安全要求

- 採用後端權限驗證。
- 使用最小權限原則。
- 高權限操作應有額外保護。
- 不允許使用者透過修改前端資料取得管理權限。
- 不允許將管理者權限寫死在前端程式碼。

## 六、學校與組織管理

### 6.1 組織列表

顯示：

- 組織名稱。
- 組織識別碼。
- 組織狀態。
- 教師人數。
- 學生人數。
- 班級數。
- 建立時間。

### 6.2 組織詳細頁

包含：

- 組織基本資訊。
- 所屬教師。
- 所屬學生。
- 班級清單。
- 課程使用情況。
- 組織管理權限。

### 6.3 組織操作

依管理者權限提供：

- 新增組織。
- 編輯組織。
- 啟用或停用。
- 管理組織成員。
- 查看組織使用統計。

## 七、班級管理

管理者可依權限查看平台班級資訊。

功能：

- 查看所有授權範圍內的班級。
- 搜尋班級。
- 查看班級教師。
- 查看學生人數。
- 檢視班級狀態。
- 處理班級異常。
- 查看班級建立及修改紀錄。

管理者介入班級管理時，必須保留操作紀錄。

## 八、課程與教材管理

### 8.1 課程管理

顯示：

- 課程名稱。
- 建立者。
- 所屬科目。
- 課程狀態。
- 建立日期。
- 更新日期。

功能：

- 搜尋課程。
- 查看課程內容。
- 審核課程。
- 啟用或下架課程。
- 查看課程修改紀錄。

### 8.2 教材管理

管理者可查看教材：

- 名稱。
- 類型。
- 所屬課程。
- 建立者。
- 授權狀態。
- 發布狀態。

對於來源或授權不明的內容，應標示待確認，不得直接當成可公開教材。

## 九、題庫管理

### 9.1 題庫總覽

顯示：

- 題目總數。
- 科目分類。
- 題型分布。
- 難度分布。
- 待審核題目。
- 停用題目。

### 9.2 題目管理

提供：

- 搜尋題目。
- 檢視題目。
- 編輯分類。
- 檢查題目狀態。
- 審核題目。
- 停用不適用題目。
- 查看修改紀錄。

### 9.3 題庫匯入

若系統支援檔案匯入，應提供：

1. 選擇檔案。
2. 檢查檔案格式。
3. 預覽匯入資料。
4. 顯示錯誤及警告。
5. 確認匯入。
6. 顯示匯入結果。

匯入失敗時，不應造成既有題庫資料不完整或錯誤覆蓋。

## 十、公告與通知管理

管理者可以依授權範圍發布平台公告。

功能：

- 建立公告。
- 編輯公告。
- 設定發布時間。
- 指定發布對象。
- 預覽公告。
- 撤回公告。
- 查看發布及通知狀態。

郵件、推播等外部服務未整合前，必須清楚標示未啟用。

## 十一、AI 服務管理

### 11.1 AI 服務狀態

顯示：

- AI 服務提供者。
- API 設定狀態。
- 連線狀態。
- 最近錯誤時間。
- 使用量。
- 服務限制。

### 11.2 AI 使用統計

依實際資料顯示：

- 請求次數。
- 成功次數。
- 失敗次數。
- 回應時間。
- 使用量或費用估算。
- 模型使用情況。

### 11.3 AI 設定

管理者可依系統授權調整：

- AI 服務提供者。
- 模型設定。
- 使用限制。
- 速率限制。
- 安全設定。
- 功能啟用狀態。

API Key 必須存放在安全的伺服器端環境，不得顯示完整金鑰或傳送至前端。

### 11.4 AI 安全與品質

提供：

- 錯誤紀錄。
- 使用者回饋統計。
- 安全事件紀錄。
- 服務品質觀察。

不得將學生的敏感對話內容無限制提供給管理者。

## 十二、平台數據分析

### 12.1 使用狀況

依實際資料呈現：

- 每日活躍使用者。
- 每週活躍使用者。
- 新增帳號數。
- 課程參與情況。
- 練習及測驗使用量。

### 12.2 學習活動

提供整體平台層級的彙總資訊：

- 練習完成量。
- 課程完成量。
- 測驗參與量。
- AI 輔助使用量。
- 學習遊戲參與量。

分析資料應以彙總資訊為主，避免不必要地暴露學生個人學習內容。

## 十三、系統監控

### 13.1 服務監控

監控項目：

- 前端服務。
- 後端 API。
- 資料庫。
- AI 服務。
- 電子郵件服務。
- 檔案儲存。
- 第三方整合服務。

### 13.2 錯誤紀錄

顯示：

- 錯誤類型。
- 發生時間。
- 影響服務。
- 錯誤識別碼。
- 處理狀態。

不得將密碼、Token、API Key 或其他敏感資訊寫入一般錯誤紀錄。

### 13.3 監控狀態

建議狀態：

- 正常。
- 注意。
- 異常。
- 未設定。
- 未啟用。

狀態必須來自實際監控結果。

## 十四、安全與操作紀錄

### 14.1 操作紀錄

重要操作應記錄：

- 操作者。
- 操作時間。
- 操作類型。
- 操作對象。
- 操作結果。
- 必要的變更摘要。

### 14.2 安全事件

顯示：

- 登入異常。
- 權限變更。
- 帳號鎖定。
- 敏感設定修改。
- 系統安全警示。

### 14.3 紀錄管理

- 僅授權管理者可查看。
- 不得任意修改歷史紀錄。
- 依資料保存政策管理保存期限。
- 避免記錄不必要的個人敏感資訊。

## 十五、系統設定

管理項目：

- 平台基本資料。
- 品牌顯示設定。
- 使用者註冊設定。
- 角色申請設定。
- 通知設定。
- 安全政策。
- 資料保存政策。
- 第三方服務設定。

修改重要設定前，應顯示變更內容並要求確認。

## 十六、資料管理與備份

### 16.1 資料管理

提供必要的資料檢查及維護功能：

- 資料完整性檢查。
- 異常資料檢查。
- 資料匯入紀錄。
- 資料匯出紀錄。

### 16.2 備份狀態

若平台已建立備份服務，可顯示：

- 最近備份時間。
- 備份結果。
- 備份檔案識別資訊。
- 備份失敗紀錄。

若未整合備份服務，應明確顯示尚未設定，不得宣稱資料已受到完整備份保護。

### 16.3 還原操作

資料還原屬於高風險操作：

- 僅限授權管理者。
- 操作前必須再次確認。
- 必須檢查備份完整性。
- 必須保留操作紀錄。
- 應先評估對現有資料的影響。

## 十七、管理者帳號安全

提供：

- 個人資料。
- 修改密碼。
- 登入紀錄。
- 登出。
- 多重要素驗證狀態（若系統已支援）。

高權限帳號應採取更嚴格的安全保護。

## 十八、管理者端資料狀態

所有管理頁面應支援：

- Loading。
- Success。
- Empty。
- Error。
- Offline。
- Unauthorized。
- Saving。

對於高風險操作，必須顯示確認畫面及操作結果。

## 十九、管理者 UI 驗收清單

- [ ] 管理者登入後進入正確的管理首頁。
- [ ] 管理功能依權限顯示。
- [ ] 使用者列表可搜尋及篩選。
- [ ] 帳號啟用、停用及鎖定流程完整。
- [ ] 角色與權限變更有後端驗證。
- [ ] 學校、組織及班級管理完整。
- [ ] 課程及教材可以審核及管理。
- [ ] 題庫可以搜尋、審核及管理。
- [ ] 題庫匯入具有預覽及錯誤處理。
- [ ] 公告發布對象及狀態正確。
- [ ] AI 設定不會暴露 API Key。
- [ ] 平台統計使用真實資料。
- [ ] 系統監控狀態來自實際服務。
- [ ] 操作及安全紀錄完整。
- [ ] 資料備份狀態不會虛報。
- [ ] 高風險操作具備確認機制。
- [ ] 桌面、平板及手機皆可正常操作。
