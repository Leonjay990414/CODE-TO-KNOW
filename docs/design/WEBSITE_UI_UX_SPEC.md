## 一、設計目標

「碼上學｜CODE TO KNOW」是一個 AI 智慧學習與教育科技平台。

網站不只是題庫或線上教學工具，而是整合課程、教材、理論學習、題目練習、模擬測驗、實作任務、AI 學習輔助及學習分析的完整學習環境。

UI/UX 設計必須達成以下目標：

1. 讓使用者快速理解平台用途。
2. 讓學生能直覺找到課程、教材及練習內容。
3. 讓 AI 成為學習輔助，而不是直接取代學生思考。
4. 讓教師能有效管理班級、課程及測驗。
5. 讓管理者能清楚管理平台資源及使用者。
6. 在電腦、平板及手機上維持一致且良好的操作體驗。

## 二、網站整體架構

網站採用「品牌首頁入口＋登入驗證＋角色專屬平台」架構。

### 2.1 使用者流程

訪客：
品牌首頁 → 了解平台 → 功能介紹 → 登入／註冊

學生：
登入 → 學生首頁 → 選擇課程 → 學習教材 → 練習題目 → AI 輔助 → 查看學習成果

教師：
登入 → 教師首頁 → 班級管理 → 課程管理 → 建立測驗 → 查看學生表現

管理者：
登入 → 管理後台 → 使用者管理 → 課程及題庫管理 → 系統管理

### 2.2 角色與權限

- 訪客：只能瀏覽公開頁面。
- 學生：只能使用已授權的學生功能及個人資料。
- 教師：依照授權管理班級、學生、課程及測驗。
- 管理者：依照管理權限管理平台資源及系統設定。

前端顯示的功能不代表使用者已取得權限，所有權限都必須由後端驗證。

## 三、全站共用版型

### 3.1 公開網站導覽列

主要項目：

- 品牌 Logo
- 首頁
- 平台介紹
- 學習功能
- AI 學習
- 課程探索
- 登入
- 免費開始學習

設計要求：

- 桌面版使用水平導覽列。
- Logo 位於左側。
- 主要導覽項目排列於中間或右側。
- 登入與註冊入口清楚可見。
- 導覽列保持簡潔，不放置過多項目。
- 捲動頁面時可使用固定式導覽列，但不得遮擋內容。

### 3.2 登入後平台版型

登入後依照角色顯示不同導覽項目。

桌面版：

- 左側側邊導覽列。
- 上方工具列。
- 中央主要內容區。
- 必要時提供右側輔助資訊區。

手機版：

- 精簡頂部導覽列。
- 主要功能使用底部導覽或可收合選單。
- 內容區改為單欄排列。

### 3.3 共用工具列

包含：

- 頁面標題或麵包屑。
- 通知入口。
- 個人帳號入口。
- 使用者頭像或預設圖示。
- 必要時提供搜尋功能。

## 四、公開首頁 UI/UX

### 4.1 首頁目標

首頁必須讓第一次進入網站的使用者，在短時間內理解：

- 碼上學是什麼。
- 可以學習哪些內容。
- AI 能如何協助學習。
- 學生與教師可以使用哪些功能。
- 如何開始使用平台。

### 4.2 首頁區塊

#### A. Hero 主視覺區

主要內容：

標題：
「讓學習不只找到答案，更真正理解知識。」

副標：
「結合理論學習、實作練習與 AI 智慧輔助，打造更完整的個人化學習體驗。」

主要按鈕：
「開始學習」

次要按鈕：
「探索平台」

視覺方向：

- 使用大面積留白。
- 以品牌色呈現主要視覺。
- 可搭配課程介面、學習數據或程式碼等視覺元素。
- 避免使用過度複雜的裝飾。
- 不使用無意義的假數據或虛構使用者評價。

#### B. 平台特色區

呈現四項主要特色：

1. 理論學習：透過課程與教材建立知識基礎。
2. 智慧練習：使用題庫與測驗檢視學習成果。
3. AI 學習輔助：透過分階段提示協助學生思考。
4. 學習分析：整理答題紀錄與需要加強的知識。

#### C. 學習流程區

以清楚的步驟呈現：

選擇課程 → 學習教材 → 練習題目 → AI 輔助 → 檢視成果

#### D. AI 學習特色區

說明 AI 不只是提供答案，而是協助學生：

- 理解題目。
- 找出關鍵條件。
- 思考解題方向。
- 檢查自己的理解。
- 整理容易出錯的觀念。

#### E. 學生與教師功能區

學生：

- 個人學習空間。
- 課程與教材。
- 練習與測驗。
- AI 學習輔助。
- 學習紀錄。

教師：

- 班級管理。
- 課程管理。
- 測驗管理。
- 學習成果檢視。
- 公告與通知。

#### F. Footer 頁尾

包含：

- 品牌名稱與簡介。
- 平台導覽連結。
- 使用條款。
- 隱私權政策。
- 聯絡資訊。

尚未建立的服務或聯絡資訊，不得使用虛構內容。

## 五、登入與註冊頁面

### 5.1 登入頁

主要元素：

- 品牌 Logo。
- 歡迎標題。
- 電子郵件欄位。
- 密碼欄位。
- 顯示／隱藏密碼。
- 記住登入狀態選項（須符合安全設計）。
- 忘記密碼。
- 登入按鈕。
- 前往註冊入口。

### 5.2 註冊頁

基本欄位：

- 姓名或顯示名稱。
- 電子郵件。
- 密碼。
- 確認密碼。
- 使用者角色或註冊類型。
- 同意服務條款與隱私權政策。

角色註冊不得直接讓任何人取得教師或管理者權限，必須經過後端授權及必要的審核流程。

### 5.3 登入狀態

必須設計：

- 正在登入。
- 登入成功。
- 帳號或密碼錯誤。
- 帳號尚未驗證。
- 帳號權限不足。
- 網路連線失敗。
- 登入逾時。

錯誤訊息必須清楚且友善，不顯示密碼、Token 或其他敏感資訊。

## 六、頁面共通互動

### 6.1 按鈕

主要按鈕：

- 使用品牌主色。
- 清楚表達操作目的。
- 提供 Hover、Focus、Active、Disabled 狀態。

次要按鈕：

- 使用淺色背景或描邊。
- 不得與主要操作按鈕產生視覺混淆。

危險操作：

- 刪除、取消授權等操作使用明確警示樣式。
- 重要操作必須再次確認。

### 6.2 表單

- 每個欄位都必須有清楚標籤。
- 必填欄位需明確標示。
- 驗證錯誤顯示在相關欄位附近。
- 不得只使用顏色表示錯誤。
- 送出時顯示處理狀態。
- 避免重複提交。

### 6.3 卡片

卡片應具有：

- 清楚標題。
- 必要的說明文字。
- 相關圖示或視覺元素。
- 明確的操作入口。

避免每一個內容都使用卡片，應依資訊層級選擇合適的呈現方式。

### 6.4 通知

通知類型：

- 成功。
- 一般資訊。
- 警告。
- 錯誤。

重要錯誤不得只短暫顯示後消失，應保留足夠資訊讓使用者理解及處理。

## 七、資料載入與空狀態

所有連接資料的頁面都必須考慮以下狀態：

1. Loading：資料載入中。
2. Success：資料成功顯示。
3. Empty：目前沒有資料。
4. Error：資料載入失敗。
5. Offline：網路中斷。
6. Unauthorized：使用者沒有權限。

空狀態應說明目前情況，並在適當時提供下一步操作。

例如：

- 尚未加入課程：提供探索課程入口。
- 尚無練習紀錄：提供開始練習入口。
- 尚無班級：提供建立班級入口。
- 搜尋沒有結果：提供修改搜尋條件的提示。

## 八、搜尋與篩選

依照不同頁面提供適當的搜尋及篩選功能。

可能的篩選條件：

- 科目。
- 課程類型。
- 難度。
- 完成狀態。
- 日期。
- 班級。
- 測驗狀態。

搜尋結果必須清楚顯示，並支援無結果狀態。

## 九、無障礙與操作體驗

- 文字與背景保持足夠對比。
- 所有操作按鈕都應可使用鍵盤操作。
- 輸入欄位必須具有可辨識標籤。
- 重要狀態不能只依靠顏色呈現。
- 圖片應提供適當替代文字。
- 動畫應避免過度快速或干擾閱讀。
- 支援使用者減少動態效果的系統偏好。

## 十、響應式設計原則

網站必須以 Responsive Web Design 為基礎。

- 桌面版：完整導覽及多欄資訊呈現。
- 平板版：適度縮減欄位及導覽寬度。
- 手機版：單欄內容、簡化導覽、適合觸控的操作元件。

具體斷點、欄位比例及手機導覽方式，以 `RESPONSIVE_DESIGN.md` 為準。

## 十一、效能與體驗要求

- 首屏優先顯示重要內容。
- 圖片應使用適當尺寸與格式。
- 避免不必要的大型動畫。
- 長列表應考慮分頁或虛擬化。
- 頁面切換應保持流暢。
- 載入失敗時提供可理解的提示。
- 不得以假資料冒充已連接的實際服務。

- [ ] 首頁能清楚介紹平台。
- [ ] 訪客能找到登入及註冊入口。
- [ ] 登入與註冊頁面具有完整狀態設計。
- [ ] 不同角色能看到對應的導覽。
- [ ] 主要頁面具備 Loading、Empty、Error 狀態。
- [ ] 表單具有驗證及錯誤提示。
- [ ] 按鈕具備完整互動狀態。
- [ ] 手機、平板及桌面版皆可正常操作。
- [ ] 介面符合品牌設計系統。
- [ ] 不存在虛構的功能完成狀態或假資料宣稱。
- [ ] 重要操作符合權限與安全要求。
