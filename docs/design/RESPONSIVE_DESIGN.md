# 響應式設計規範（RESPONSIVE DESIGN）

**專案名稱：** 碼上學｜CODE TO KNOW  
**文件路徑：** `docs/design/RESPONSIVE_DESIGN.md`  
**文件用途：** 定義平台在不同螢幕尺寸、裝置及使用情境下的版面配置、互動方式與顯示規則。

---

## 1. 設計目標

碼上學採用 Responsive Web Design（RWD，響應式網頁設計），讓使用者能在桌上型電腦、筆記型電腦、平板及手機上獲得一致且完整的學習體驗。

設計原則：

1. **內容優先：** 不同裝置都能清楚閱讀課程、題目及學習資料。
2. **操作一致：** 核心功能在各裝置上都能正常使用。
3. **版面彈性：** 依螢幕寬度調整欄位、間距、字體及元件排列。
4. **觸控友善：** 手機和平板操作時，按鈕與互動區域應方便點擊。
5. **效能優先：** 避免小螢幕載入不必要的大型圖片或動畫。
6. **無障礙考量：** 保持足夠的文字對比、清楚的操作狀態及合理的閱讀順序。

## 2. 裝置與斷點規劃

採用以下初始響應式斷點，實際開發時可依元件需求微調。

| 裝置類型 | 螢幕寬度 | 主要版面 |
| --- | ---: | --- |
| 小型手機 | 320–374px | 單欄、精簡導覽 |
| 一般手機 | 375–767px | 單欄、底部或收合式導覽 |
| 平板 | 768–1023px | 一至兩欄、可收合側邊欄 |
| 小型桌面 | 1024–1279px | 完整側邊導覽、彈性內容區 |
| 大型桌面 | 1280px 以上 | 多欄資訊、完整工作區 |

開發時應採用 Mobile First（行動裝置優先）方式撰寫樣式，再逐步擴展至較大的螢幕。

## 3. 全站共用版面

### 3.1 導覽列

**桌面版：**

- 顯示品牌標誌、主要導覽、登入或使用者資訊。
- 導覽項目保持清楚，不過度擁擠。
- 可使用固定或吸頂式導覽，但不得遮擋主要內容。

**平板版：**

- 保留品牌標誌與主要功能入口。
- 空間不足時，將次要選項收合至選單。
- 避免導覽列佔據過多垂直空間。

**手機版：**

- 顯示品牌標誌與選單按鈕。
- 主要導覽改為收合式選單或適合觸控的導覽方式。
- 登入、註冊等重要操作仍應容易找到。

### 3.2 內容容器

- 桌面版可使用較寬的內容區域。
- 平板版依可用寬度調整左右留白。
- 手機版採單欄排列，保留適當邊距。
- 長篇文字不得貼齊螢幕邊緣。
- 避免固定寬度造成水平捲動。

### 3.3 卡片與資訊區塊

- 大型螢幕可使用多欄卡片。
- 平板依空間調整為兩欄或單欄。
- 手機原則上採單欄排列。
- 卡片內容過長時應自然延伸，不得截斷重要資訊。

## 4. 學生端響應式規範

### 4.1 學生首頁

桌面版：

- 可使用側邊導覽與多欄資訊卡。
- 顯示學習進度、課程、近期測驗及學習提醒。

手機版：

- 將資訊依重要程度垂直排列。
- 優先呈現今日學習、繼續課程及近期任務。
- 圖表可改為簡化圖表或摘要數據。

### 4.2 課程與教材

- 課程列表依裝置調整卡片數量。
- 教材閱讀區應保留舒適的行距與字體大小。
- PDF 或其他教材應提供適合小螢幕的檢視方式。
- 不得只提供桌面版才能使用的教材功能。

### 4.3 題庫與練習

- 題目、選項及作答按鈕應清楚排列。
- 手機版以單欄呈現題目及選項。
- 長題目可自然換行。
- 作答按鈕應保持容易點擊。
- 題號、作答進度及剩餘時間應清楚顯示。

### 4.4 考試模式

- 考試畫面應減少不必要的裝飾。
- 手機版仍須清楚顯示題目、選項與作答狀態。
- 重要操作不得只依賴滑鼠懸停。
- 提交考卷前應提供清楚的確認步驟。
- 若特定實作題需要桌面環境，應在開始前明確告知設備需求，不得讓使用者做到一半才發現無法操作。

### 4.5 AI 學習助理

- 桌面版可採側邊面板或獨立對話區。
- 手機版可改為獨立頁面或全螢幕對話介面。
- 對話內容應自動換行。
- 提示層級、引用題目及操作按鈕應清楚區分。
- 不得因螢幕縮小而隱藏必要的 AI 提示內容。

### 4.6 學習分析

- 桌面版可呈現完整圖表與多項數據。
- 手機版優先呈現重點摘要。
- 複雜圖表可改為簡化圖表或可切換的資料區塊。
- 數據應搭配文字說明，不能只靠顏色區分。

### 4.7 學習遊戲

- 遊戲操作需支援觸控及滑鼠。
- 手機版應重新安排操作按鈕位置。
- 不得讓重要操作超出可視範圍。
- 遊戲開始前應顯示規則及操作說明。
- 若遊戲有最低螢幕尺寸或設備需求，應事先告知。

## 5. 教師端響應式規範

### 5.1 教師首頁

- 桌面版呈現班級概況、近期考試及學生學習狀況。
- 平板版可將資訊卡重新排列。
- 手機版優先顯示重要提醒及近期任務。

### 5.2 班級管理

- 桌面版可使用完整表格。
- 手機版應改用學生資訊卡或可橫向檢視的表格。
- 搜尋、篩選及班級切換功能應保留。
- 不得因版面縮小而遺失學生資料。

### 5.3 考試管理

- 考試建立表單應依裝置調整欄位排列。
- 手機版採垂直表單。
- 重要設定應有清楚標籤及說明。
- 考試發布、取消及刪除等操作應有確認機制。

### 5.4 成績與學習報告

- 桌面版提供完整成績表及分析圖表。
- 手機版提供重點摘要及個別學生檢視。
- 匯出報表等較複雜操作可優先安排於桌面版，但手機仍應能查看必要資料。

## 6. 管理端響應式規範

- 管理首頁需支援桌面、平板及手機。
- 使用者、角色、權限及系統設定應保持清楚分類。
- 大型資料表在手機版可改為資訊卡。
- 危險操作應保持清楚的確認流程。
- 系統狀態、錯誤訊息及操作結果應在各裝置上清楚顯示。

## 7. 表單與輸入元件

所有表單應符合以下規範：

1. 標籤不得只依賴 placeholder 呈現。
2. 輸入欄位應配合裝置寬度調整。
3. 錯誤訊息應顯示在對應欄位附近。
4. 必填欄位應清楚標示。
5. 手機輸入時應選擇適當的鍵盤類型。
6. 表單提交後應提供明確結果。
7. 多欄表單在手機版應改為單欄排列。

## 8. 觸控與操作規範

- 主要互動元件建議至少提供約 44 × 44 CSS px 的觸控區域。
- 按鈕之間應保留足夠間距。
- 不得只用 hover 才能顯示重要資訊。
- 下拉選單、彈出視窗及日期選擇器需支援觸控。
- 重要功能應提供清楚的操作回饋。
- 避免使用需要精準拖曳才能完成的必要操作。

## 9. 文字與排版

- 使用 Noto Sans TC 作為主要繁體中文字體。
- 英文與數字使用 Inter。
- 程式碼使用 JetBrains Mono。
- 手機版內文應保持容易閱讀。
- 標題依螢幕尺寸調整，不得過大而擠壓內容。
- 長網址、程式碼及英文單字應避免破壞版面。
- 不得因響應式縮放而使文字過小。

## 10. 圖片、圖表與媒體

- 圖片應設定合理的最大寬度及比例。
- 優先使用適合裝置尺寸的圖片資源。
- 圖片不得超出容器。
- 圖表應支援縮放、簡化或替代資料呈現。
- 影片播放器應依容器寬度調整。
- 大型動畫及 3D 元件應考量低效能裝置的載入速度。
- 非必要動畫可在使用者偏好減少動態效果時降低或停用。

## 11. 無障礙與可用性

- 文字與背景應保持足夠對比。
- 互動元件需有明確的焦點狀態。
- 圖片應提供適當替代文字。
- 表單欄位需有可辨識標籤。
- 不得只使用顏色傳達錯誤或成功狀態。
- 支援鍵盤操作及合理的 Tab 順序。
- 尊重使用者的減少動態效果設定。

## 12. 效能規範

- 避免一次載入不必要的大型元件。
- 圖片應壓縮並使用適當格式。
- 長列表可採分頁或虛擬化。
- 大型圖表及 3D 元件可延遲載入。
- 避免大量動畫同時執行。
- 手機網路環境下應優先載入核心內容。
- 載入中、空資料及錯誤狀態都應有清楚的畫面。

## 13. 測試裝置與測試範圍

至少應測試以下尺寸：

| 測試類型 | 建議尺寸 |
| --- | --- |
| 小型手機 | 320 × 568 |
| 一般手機 | 375 × 812 |
| 大型手機 | 430 × 932 |
| 平板直向 | 768 × 1024 |
| 平板橫向 | 1024 × 768 |
| 筆記型電腦 | 1366 × 768 |
| 桌上型螢幕 | 1920 × 1080 |

測試項目：

- 版面是否溢出或出現非預期水平捲動。
- 導覽列及選單是否正常。
- 表單是否能輸入及提交。
- 題目、選項及作答功能是否正常。
- AI 對話是否能完整閱讀及操作。
- 圖表是否能清楚呈現。
- 教師與管理端表格是否能在小螢幕檢視。
- 觸控按鈕是否容易操作。
- 不同裝置上的字體、圖片及動畫是否正常。

## 14. 驗收標準

完成響應式設計後，應符合以下條件：

- [ ] 支援手機、平板及桌面瀏覽器。
- [ ] 核心功能在不同裝置上均可使用。
- [ ] 重要內容不會因螢幕尺寸而消失。
- [ ] 不會出現非預期的水平捲動。
- [ ] 表單、選單及按鈕支援觸控。
- [ ] 學生端、教師端及管理端均完成響應式調整。
- [ ] 題庫、考試、AI 助理及學習分析均完成測試。
- [ ] 圖片、圖表及動畫不會造成明顯版面問題。
- [ ] 符合基本無障礙及效能要求。
