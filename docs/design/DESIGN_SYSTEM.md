- 文件版本：v1.0

# 一、品牌視覺定位

## 1.1 設計目標

「碼上學｜CODE TO KNOW」應呈現成熟、專業、現代的國際教育科技品牌形象。

視覺上避免：

- 傳統補習班式的大量促銷區塊。
- 過度鮮豔的色彩。
- 過度可愛或幼兒化的插畫。
- 大量無意義的裝飾動畫。
- 每個頁面使用不同風格的元件。
- 為了科技感而堆疊過多光效、漸層及粒子。

核心風格：

- Premium：高質感。
- Minimal：簡約。
- Modern：現代。
- Educational：教育導向。
- Technology：科技感。
- Approachable：容易親近。

## 1.2 品牌核心理念

AI 協助學習，但不取代思考。

所有介面設計都應讓使用者更容易理解資訊、找到功能並完成學習任務。

# 二、色彩系統

## 2.1 品牌色彩

| 色彩名稱 | 色碼 | 用途 |
| --- | --- | --- |
| 暖象牙白 | #F5F2EA | 主要背景 |
| 深霧藍灰 | #526B7B | 品牌主色 |
| 霧藍 | #8FA9B8 | 輔助色 |
| 淺藍灰 | #D9E2EA | 區塊背景 |
| 自然中性色 | #D9D2C4 | 中性裝飾 |
| 柔霧粉 | #E8DCD8 | 少量點綴 |
| 香檳金 | #BDA77E | 重要視覺重點 |
| 石墨灰 | #26343D | 主要文字 |

## 2.2 使用比例

建議以以下比例作為起點：

- 60%：白色、暖象牙白及淺色背景。
- 25%：霧藍與淺藍灰。
- 10%：石墨灰及其他中性色。
- 5%：香檳金與柔霧粉等點綴色。

此比例為視覺參考，不是每個頁面都必須精確符合。

## 2.3 功能狀態色

品牌色不能取代功能狀態色。

- 成功：使用清楚、易辨識的綠色。
- 警告：使用適度的黃色或橘色。
- 錯誤：使用紅色。
- 資訊：使用藍色。

狀態不能只依賴顏色表示，必須搭配文字或圖示。

# 三、字體系統

## 3.1 字體

- 中文：Noto Sans TC。
- 英文：Inter。
- 程式碼：JetBrains Mono。

## 3.2 字級

| 層級 | 建議尺寸 | 用途 |
| --- | ---: | --- |
| Display | 48–64px | 品牌首頁主視覺 |
| H1 | 36–44px | 頁面主標題 |
| H2 | 28–32px | 主要區塊標題 |
| H3 | 22–24px | 次要區塊標題 |
| H4 | 18–20px | 卡片及小區塊標題 |
| Body Large | 16–18px | 主要說明 |
| Body | 14–16px | 一般內容 |
| Caption | 12–13px | 輔助資訊 |

手機版需適度縮小標題，避免文字超出畫面。

## 3.3 排版原則

- 主要內容保持清楚的閱讀順序。
- 避免長篇文字全部使用相同字級。
- 重要數據應有明確視覺層級。
- 行距需保持舒適。
- 英文與中文混排時注意字體比例。

# 四、間距與版面系統

## 4.1 間距基準

使用 4px 作為基本間距單位。

| Token | 尺寸 |
| --- | ---: |
| space-1 | 4px |
| space-2 | 8px |
| space-3 | 12px |
| space-4 | 16px |
| space-5 | 20px |
| space-6 | 24px |
| space-8 | 32px |
| space-10 | 40px |
| space-12 | 48px |
| space-16 | 64px |
| space-20 | 80px |

## 4.2 版面原則

桌面版：

- 使用完整可利用的內容寬度。
- 儀表板採側邊導覽與主要內容區。
- 避免所有頁面都使用固定置中窄版。
- 長篇內容應有合理的最大閱讀寬度。

平板：

- 依照空間調整雙欄配置。
- 側邊導覽可收合。
- 表格允許適當的橫向捲動。

手機：

- 以單欄資訊為主。
- 按鈕及操作區需方便觸控。
- 避免桌面版直接縮小後使用。
- 重要操作應容易找到。

# 五、圓角、邊框與陰影

## 5.1 圓角

| Token | 尺寸 | 用途 |
| --- | ---: | --- |
| radius-sm | 6px | 小型標籤 |
| radius-md | 10px | 輸入框及按鈕 |
| radius-lg | 16px | 卡片 |
| radius-xl | 24px | 大型區塊 |
| radius-full | 999px | 膠囊按鈕 |

## 5.2 邊框

- 使用淺色細邊框。
- 不應讓每個區塊都出現明顯框線。
- 重要區塊可透過背景色區隔。
- Focus 狀態必須明顯。

## 5.3 陰影

- 預設採用柔和、低對比陰影。
- Hover 時可增加少量浮起效果。
- 避免厚重黑色陰影。
- 不得讓陰影影響文字辨識。

---

# 六、共用 UI 元件

所有平台應使用共用元件，避免重複製作不同版本。

## 6.1 按鈕

類型：

1. Primary：主要操作。
2. Secondary：次要操作。
3. Outline：外框操作。
4. Ghost：低干擾操作。
5. Danger：刪除或危險操作。

每種按鈕需具備：

- Default。
- Hover。
- Focus。
- Pressed。
- Disabled。
- Loading。

按鈕必須具有明確功能，不可使用沒有實際操作的假按鈕。

## 6.2 卡片

卡片適用於：

- 課程。
- 學習任務。
- 成績摘要。
- 學習統計。
- 成就。
- 教師班級資訊。

卡片應包含明確標題、必要資訊及可理解的操作入口。

## 6.3 輸入元件

共用元件：

- Text Input。
- Password Input。
- Search Input。
- Textarea。
- Select。
- Checkbox。
- Radio。
- Switch。
- Date Picker。

每個輸入欄位都應具有標籤、必要提示及錯誤訊息。

## 6.4 表格

表格用於教師及管理員的資料管理。

要求：

- 表頭清楚。
- 欄位名稱易懂。
- 支援排序及分頁。
- 手機版提供適當的呈現方式。
- 沒有資料時顯示空狀態。
- 操作按鈕需清楚標示。

## 6.5 對話框

適用於：

- 刪除確認。
- 提交考試。
- 重要設定變更。
- 權限不足提示。
- 成功或錯誤通知。

重要操作不可只依賴短暫消失的提示訊息。

# 七、圖示與圖片規範

## 7.1 圖示

- 使用一致的圖示風格。
- 優先採用簡潔線性圖示。
- 圖示應有明確語意。
- 不可在同一區域混用過多不同風格。

## 7.2 圖片

- 優先使用具有教育及科技情境的高品質圖片。
- 圖片需符合品牌色彩。
- 避免低品質、過度卡通化的素材。
- 需要替代文字以支援輔助閱讀。
- 不可使用未取得授權的圖片。

## 7.3 Logo

正式 Logo 尚未完成。

在 Logo 定稿前：

- 預留標誌位置。
- 不自行製作替代標誌。
- 不將文字商標誤當成正式 Logo 圖檔。
- 正式 Logo 應提供 SVG、PNG、反白及單色版本。

# 八、動畫與互動規範

## 8.1 動畫原則

動畫必須協助使用者理解操作結果，而不是單純裝飾。

建議時間：

| 類型 | 建議時間 |
| --- | ---: |
| Hover | 120–180ms |
| 按鈕回饋 | 100–160ms |
| 卡片進場 | 200–300ms |
| 對話框 | 180–250ms |
| 頁面區塊進場 | 300–500ms |

## 8.2 互動效果

- 按鈕 Hover 時改變背景或邊框。
- 卡片 Hover 時輕微浮起。
- 頁面區塊可淡入。
- 圖表可使用簡單進場動畫。
- AI 回答可逐步呈現。
- 表單錯誤應立即提供清楚提示。

## 8.3 動畫限制

- 不可影響文字閱讀。
- 不可阻礙按鈕操作。
- 不可讓重要資訊延遲出現。
- 不可使用無限循環且沒有意義的動畫。
- 支援減少動態效果的系統偏好。

---

# 九、狀態與回饋規範

每個主要頁面都需考慮以下狀態：

1. Loading：載入中。
2. Success：操作成功。
3. Error：操作失敗。
4. Empty：目前沒有資料。
5. Disabled：目前不可操作。
6. No Permission：沒有權限。
7. Offline：網路中斷。

不得只設計正常情況，忽略錯誤及例外情況。

---

# 十、無障礙與使用性

- 文字與背景需有足夠對比。
- 互動元件需可使用鍵盤操作。
- 表單欄位需有明確標籤。
- 圖片提供替代文字。
- 錯誤訊息應指出問題。
- 不只使用顏色傳達資訊。
- 支援減少動態效果。
- 重要操作區域需方便觸控。

# 十一、響應式設計

建議斷點：

| 裝置 | 寬度 |
| --- | --- |
| Mobile | 小於 640px |
| Tablet | 640–1023px |
| Desktop | 1024px 以上 |
| Wide Desktop | 1440px 以上 |

實際版面應依內容彈性調整，不得只依賴固定寬度。
