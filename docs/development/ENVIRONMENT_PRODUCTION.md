# ENVIRONMENT_PRODUCTION.md

# 碼上學｜CODE TO KNOW 正式環境規劃

## 一、文件目的

規劃 CODE TO KNOW 未來正式網站的部署環境及上線管理方式，確保系統能穩定、安全地提供使用者使用。

本文件為預先規劃，並不代表正式伺服器、網域或雲端服務已經建置完成。

## 二、正式環境架構

正式環境預計包含以下部分：

1. 前端網站：提供使用者瀏覽及操作。
2. 後端服務：處理登入、權限、資料及系統功能。
3. 資料庫：保存使用者、課程、題庫及學習紀錄。
4. AI 服務：提供題目解析、學習提示及輔助功能。
5. 檔案儲存：保存教材、圖片及相關學習資源。
6. 部署平台：負責網站及後端服務的運行。

實際採用的服務與架構，將於第 8 階段技術選型後確認。

## 三、正式環境與開發環境區分

| 環境 | 主要用途 |
| --- | --- |
| 開發環境 | 開發及初步測試 |
| 測試環境 | 功能整合與品質驗證 |
| 正式環境 | 提供正式使用者使用 |

不同環境應使用各自的設定及資料，不可將開發測試資料直接當成正式資料。

## 四、網域與連線安全

正式網站上線前，預計完成：

- 設定正式網站網域。
- 啟用 HTTPS 安全連線。
- 確認網域與伺服器連線正常。
- 設定必要的安全標頭。
- 確認 API 使用安全連線。
- 避免在公開頁面暴露內部系統資訊。

網域名稱及服務供應商尚待評估，不預先假設已經取得。

## 五、環境變數與機密管理

正式環境所需設定應透過環境變數或安全的機密管理服務保存。

可能包含：

- 資料庫連線設定
- JWT 或工作階段簽章金鑰
- AI API 金鑰
- Google 登入相關設定
- 電子郵件服務設定
- 檔案儲存服務設定

安全規範：

1. 不可將 API 金鑰直接寫入前端程式碼。
2. 不可將密碼或私密金鑰提交至 GitHub。
3. 正式環境與開發環境應使用不同的機密設定。
4. 機密外洩時應立即更新相關金鑰。
5. `.env` 等機密設定檔不得公開上傳。

## 六、資料庫與資料管理

正式資料庫應具備：

- 使用者資料管理
- 課程與教材資料管理
- 題庫及測驗紀錄
- 學習進度紀錄
- 教師與班級資料
- 遊戲及獎勵紀錄

資料管理原則：

- 限制資料庫存取權限。
- 定期備份重要資料。
- 建立資料還原流程。
- 避免未授權存取及資料外洩。
- 資料異動應保留必要紀錄。

實際資料庫種類及備份頻率，待技術架構確定後制定。

## 七、正式部署流程

正式上線預計依照以下流程執行：

1. 完成開發功能。
2. 執行功能與整合測試。
3. 確認安全性及權限設定。
4. 檢查正式環境變數。
5. 建置正式版本。
6. 部署前端及後端服務。
7. 確認資料庫連線。
8. 檢查網站及 API 是否正常。
9. 執行上線後驗收。
10. 紀錄版本及部署結果。

若發現重大問題，應暫停發布或依照回復計畫處理。

## 八、備份與災難復原

正式環境應建立資料備份與復原規劃。

預計措施：

- 定期備份資料庫。
- 保存重要系統設定。
- 確認備份檔案可正常使用。
- 建立資料還原程序。
- 記錄重大異常及處理方式。
- 定期檢查備份是否完整。

實際備份週期及保存期限，將依資料量與服務成本決定。

## 九、系統監控與維護

正式網站上線後，應持續注意：

- 網站是否正常運作
- 伺服器資源使用情況
- API 回應及錯誤紀錄
- 資料庫連線狀態
- AI 服務連線狀態
- 使用者登入異常
- 系統安全事件

發生異常時，應記錄問題、確認影響範圍並安排修正。
