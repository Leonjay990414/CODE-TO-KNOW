## 一、審查範疇與教育核心哲學

第 5 波聚焦於強化「碼上學（CODE TO KNOW）」三大最具前瞻性與體驗價值的核心面向：**AI 智慧家教、遊戲化學習互動、以及品牌數位行銷傳播**。

在進行技術審查前，必須重申平台不可動搖的教育核心原則：
1. **AI 輔助思考而非替代思考**：
   - 品牌精神「碼上學，學無止境（Learn Beyond Limits）」。
   - AI 家教絕不能直接輸出完整解答代碼或代寫作業，必須依循「四階段漸進式鷹架引導」（概念聚焦 $\to$ 破題思路 $\to$ 邊界提示 $\to$ 架構解構）。
2. **遊戲化服務於學習成就而非單純娛樂**：
   - 遊戲關卡緊扣「網頁設計丙級」檢定核心技能（HTML 結構、CSS 樣式排版、JavaScript 邏輯除錯）。
   - 具備清晰的任務引導（Briefing）、三星評分（Star Rating）與成就勳章（Badges）。
3. **品牌傳播建立在真實實力與教育誠信**：
   - 數位行銷與展示頁面必須忠實呈現產品功能與雙版本（版本 A 檢定與版本 B 影音）之教學實力，嚴禁虛構不實功能。

## 四、核心缺口與技術風險分析

在進入第 5 波規劃前，必須正視以下 5 大關鍵技術落差與架構風險：

1. **外部 API 依賴與資安外洩風險**：
   - 若直接在前端呼叫 OpenAI 或 Gemini API，將不可避免地暴露 API Key。
   - **防範策略**：必須由後端提供 `/api/ai/chat` 代理路由，前端絕不持有金鑰。同時必須設計「離線規則備援引擎」，在無 API Key 或無網路環境下依然能透過內建知識庫正常運作。
2. **AI 學生作答直接抄襲風險**：
   - 學生可能將檢定考題直接貼入提問框，要求 AI 給予完整代碼。
   - **防範策略**：在系統提示詞與前置中介軟體實施「教育防護罩（Pedagogical Guardrails）」，嚴格限制輸出格式為「啟發性引導」，主動過濾直接解答。
3. **資料庫 `AUTH-03` 隔離限制**：
   - 由於雲端資料庫受 `AUTH-03` 阻斷，遊戲進度、成就紀錄與 AI 對話歷史無法寫入遠端 PostgreSQL。
   - **防範策略**：持續沿用經第 2、3、4 波驗證成熟的「本機身分隔離儲存技術（User-Scoped LocalStorage）」，確保單機體驗完整且在無連線狀態下零崩潰。
4. **遊戲無障礙與鍵盤導航挑戰**：
   - 拖曳式拼圖（Drag and Drop）與視覺樣式調整通常極度依賴滑鼠。
   - **防範策略**：必須為每款遊戲提供等效的鍵盤替代方案（如 Enter 選取、方向鍵移動、數字鍵切換），符合 WCAG 2.1 AA 無障礙標準。
5. **行銷頁面與既有首頁割裂風險**：
   - 避免新增不符專案高雅專業調性的花俏元件。
   - **防範策略**：嚴格依循品牌色（Warm Ivory, Misty Blue Gray, Champagne Gold）與字型（Noto Sans TC, Inter），保持高雅沉穩的國際 EdTech 風範。
