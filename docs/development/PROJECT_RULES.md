## 一、專案基本定位

「碼上學｜CODE TO KNOW」是一個以 AI 技術為輔助的智慧學習與教育科技平台。

平台整合課程、學習資源、題庫、練習、測驗、實作及互動式學習體驗，協助使用者建立知識理解與自主學習能力。

核心理念：

**AI 協助學習，不取代獨立思考。**

## 二、專案開發原則

1. 所有功能必須以實際需求為依據，不隨意增加無關功能。
2. 優先確保系統穩定、安全及易於維護。
3. 採用模組化設計，避免所有功能集中在單一程式檔案。
4. 重視電腦、平板及手機的跨裝置使用體驗。
5. 所有重要功能都應有適當的測試。
6. 不得將尚未完成的功能標示為正式上線。
7. 不得虛構 API、資料、測試結果或系統功能。
8. 開發前應先確認需求、影響範圍及預期成果。

## 三、品牌與介面規範

1. 正式品牌名稱統一使用「碼上學｜CODE TO KNOW」。
2. 不得混用其他舊專案的名稱或品牌識別。
3. 整體視覺以專業、現代、簡潔及具有科技教育感為方向。
4. 優先採用淺色系及清晰的資訊層級。
5. 不得任意更改已確認的品牌標準。
6. 介面應保持一致的按鈕、卡片、表單、圖示及互動規則。
7. 所有中文介面以繁體中文為主要語言。

## 四、程式碼管理規範

1. 程式碼應具備清楚的命名及合理的檔案結構。
2. 避免重複程式碼，適當拆分共用元件與功能模組。
3. 不得任意刪除或覆蓋已完成的功能。
4. 修改既有功能前，應先理解原有程式碼及其依賴關係。
5. 不得在正式程式碼中留下明顯未完成的測試內容。
6. 重要修改應留下 Git Commit 紀錄。
7. 不得未經確認就執行可能造成資料遺失的操作。

## 五、AI Agent 協作規範

1. AI Agent 必須先理解專案需求及相關文件，再執行開發。
2. 執行大型修改前，應先提出實作計畫。
3. 不得自行變更已確認的品牌名稱、產品方向及核心架構。
4. 不得擅自刪除重要檔案或修改無關模組。
5. 遇到不確定的需求或高風險操作，應先說明並取得確認。
6. 完成工作後，應說明修改內容、涉及檔案及測試結果。
7. 不得宣稱未實際執行的測試已經通過。

## 六、資訊安全規範

1. 不得將 API Key、密碼、Token 或私人憑證寫入公開程式碼。
2. 敏感環境設定應使用環境變數管理。
3. `.env` 等敏感檔案不得提交至 Git。
4. 使用者密碼不得以明文儲存。
5. 必須考慮登入驗證、權限控管及資料存取安全。
6. 不得在未取得授權的情況下存取他人資料。
7. 正式環境與測試環境不得共用不適當的敏感資料。

## 七、資料與資料庫管理

1. 資料庫結構應有清楚的設計與文件紀錄。
2. 重要資料修改應考慮備份及復原方式。
3. 不得任意刪除正式使用者資料。
4. 不得將測試資料誤當成正式資料。
5. 資料欄位及 API 格式應保持一致。
6. 涉及個人資料時，應遵守適用的隱私與資料保護要求。

## 八、測試與品質管理

1. 新增功能應進行適當測試。
2. 修復錯誤後應確認原有功能沒有受到影響。
3. 重要操作應測試正常與異常情況。
4. 介面應檢查不同螢幕尺寸。
5. 發現錯誤應留下紀錄並追蹤修正。
6. 未完成必要測試的功能不得直接視為正式完成。

## 九、Git 與版本管理

1. 主要分支統一使用 `main`。
2. 每次重要修改應建立清楚的 Commit。
3. Commit 訊息應簡潔並能說明修改目的。
4. 未經確認不得強制覆寫遠端分支。
5. 推送前應檢查變更內容。
6. 不得將密碼、Token 或敏感資料提交至 Repository。
7. 重要版本應保留可追蹤的紀錄。

## 十、文件管理規範

1. 專案規劃文件放置於 `docs/planning/`。
2. 系統架構文件放置於 `docs/architecture/`。
3. 開發管理文件放置於 `docs/development/`。
4. 品牌素材放置於 `branding/`。
5. 文件應標示名稱、版本及更新狀態。
6. 重大規劃變更應同步更新相關文件。
7. 文件內容應與實際系統狀態一致。

## 十一、功能完成標準

每項功能至少應確認：

- 需求與預期成果明確。
- 功能已實際實作。
- 主要操作流程正常。
- 重要異常情況已處理。
- 必要測試已執行。
- 文件與實際功能一致。
- Git 版本紀錄已建立。

## 十二、規則更新

本文件為專案初版管理規範。

未來可依照實際開發情況持續更新，但任何重大規則調整都應保留版本紀錄，並確保相關開發文件同步更新。
