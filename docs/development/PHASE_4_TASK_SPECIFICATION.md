- 執行 Commit、Push、Deploy。
- 執行 `git reset --hard`、`git clean`、Force Push。
- 使用 `git add .` 或 `git add -A`。
- 擅自修改 AUTH-03 的阻塞狀態。

# 二、本波核心目標

本波的重點不是增加大量管理員頁面，而是讓平台管理員可以透過真實資料與現有授權，掌握整個平台的運作情況。

必須以以下八個面向進行盤點與改善。

## A. 平台管理員首頁

檢查並改善管理員首頁。

應盤點是否能真實呈現：

- 平台學生帳號數量。
- 教師帳號數量。
- 待審核教師申請數。
- 已核准教師數量。
- 平台班級數量。
- 最近管理活動。
- 系統健康狀態。
- 管理員常用功能入口。

每項統計必須確認真實資料來源。

沒有 API 支援的統計，不得使用硬編碼數字。

應顯示：

- 尚無資料。
- 暫無統計。
- 資料來源尚未提供。

不得讓管理員誤以為假數據是真實平台統計。

## B. 帳號管理

盤點現有帳號管理能力。

檢查是否能夠：

- 搜尋帳號。
- 查看帳號基本資料。
- 查看帳號角色。
- 查看帳號狀態。
- 查看註冊時間。
- 查看現有可取得的帳號活動。
- 區分學生與教師。
- 檢視帳號權限。

若現有 API 支援，整合相關功能。

若不支援帳號停用、刪除、重設權限或其他高影響操作，必須列為未完成，不得自行建立前端假操作。

特別注意：

帳號刪除、角色變更、權限升級均屬高影響操作，不能只靠前端按鈕實現。

## C. 教師申請審核

這是管理員平台的重要功能。

已知專案已有 TeacherApplication 與管理員核准流程，應優先檢查既有實作。

確認是否具備：

- 待審核申請列表。
- 申請者基本資料。
- 申請狀態。
- 申請時間。
- 審核紀錄。
- 核准操作。
- 拒絕操作。
- 操作確認。
- 審核結果提示。
- 重複提交防護。
- 審核權限保護。

必須使用真實 API 與資料。

若既有功能已經完善，優先保留，不要重新開發一套重複系統。

不得在未授權下修改教師審核後端流程。

## D. 全平台班級治理

管理員與教師的班級管理範圍不同。

教師管理自己有權限管理的班級；管理員則依現有權限查看平台層級的班級資料。

盤點：

- 平台班級列表。
- 班級基本資料。
- 班級建立者。
- 班級學生人數。
- 班級建立時間。
- 班級狀態。
- 班級搜尋與篩選。
- 班級詳細資料。

若現有 API 僅支援教師自己的班級，不能假裝管理員已能查看全平台班級。

若缺少管理員層級的 API，列入後續需求。

不得透過前端繞過後端權限取得資料。

## E. 系統健康與營運監控

盤點現有系統健康檢查能力。

已知專案有 `/api/health` 健康探針，應先確認其實際回傳內容與使用方式。

可改善：

- API 連線狀態展示。
- 前端服務狀態。
- 最近健康檢查結果。
- 錯誤狀態提示。
- 系統資訊說明。
- 健康檢查載入狀態。

若現有健康探針不提供資料庫、郵件、AI 或其他服務的獨立狀態，不得自行顯示為正常。

不得暴露：

- 資料庫連線字串。
- API 金鑰。
- Session Secret。
- 環境變數。
- 伺服器內部機密。
- 個人敏感資料。
- 詳細堆疊追蹤給一般使用者。

健康狀態應採取最小資訊揭露原則。

## F. 操作紀錄與稽核

已知專案具有 AuditLog 相關功能，應先盤點現有資料與 API。

確認是否能呈現：

- 操作者。
- 操作類型。
- 操作時間。
- 操作結果。
- 相關目標。
- 可取得的紀錄篩選。
- 詳細紀錄檢視。

不得自行捏造操作紀錄。

若沒有完整稽核資料來源，應明確標示缺少的資料欄位或 API。

不得修改 AuditLog 後端模型或寫入邏輯。

管理員介面不得讓一般學生或教師讀取不應取得的稽核資料。

## G. 平台內容與功能治理

盤點目前是否存在：

- 認證項目管理。
- 題庫管理。
- 教材管理。
- 平台公告。
- 內容審核。
- 學習資源管理。
- 平台設定。

逐項確認是否具有真實資料模型、API、權限及測試。

尤其必須保護五大正式術科題組：

1. 104301 校園社團介紹網。
2. 104302 運動廣場連結網。
3. 104303 國家公園介紹網。
4. 104304 網路行銷購物網。
5. 104305 書曼的旅遊相簿。

不得在本波修改五大題組的題目、教材、步驟、答案、範例程式、評分、檢核及完成條件。

若管理員需要查看術科題組資料，只能使用既有唯讀功能。

老師完整資料尚未到齊，不得開始題組專屬重構。

## H. 管理員 UI/UX、RWD 與無障礙

管理員後台應與品牌視覺一致。

設計原則：

- 專業、簡潔、成熟。
- 資訊層級清楚。
- 表格及統計資料易閱讀。
- 淺鼠尾草綠、燕麥色、奶油白、藍灰及適量香檳金。
- 不過度裝飾。
- 不以大量動畫干擾管理工作。
- 不為了美觀犧牲資訊可讀性。

至少檢查：

320、340、360、375、390、414、430、480、667、768、840、1024、1280、1440、1920 px。

確認：

- 無不合理水平溢出。
- 管理表格能在小螢幕使用。
- 搜尋欄與篩選器能合理排列。
- 操作按鈕不重疊。
- 文字不會被截斷。
- Modal 不超出視窗。
- 觸控目標盡量達 44px。
- 鍵盤操作正常。
- Focus 狀態明確。
- 載入、空資料及錯誤狀態一致。

必須區分瀏覽器尺寸模擬與實體設備測試。
