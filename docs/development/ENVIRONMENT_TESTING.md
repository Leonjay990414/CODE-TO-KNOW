# ENVIRONMENT_TESTING.md

# 碼上學｜CODE TO KNOW 測試環境與品質驗證規劃

## 一、文件目的

建立 CODE TO KNOW 專案的測試規範，確保未來網站功能、資料處理、AI 服務及使用者操作流程能正常運作。

本文件屬於測試規劃，並不代表相關測試工具或測試程式已經完成安裝。

## 二、測試基本原則

1. 每項功能完成後，應進行基本測試。
2. 不可只確認畫面能顯示，也要確認操作結果正確。
3. 涉及使用者資料的功能，必須確認資料儲存及讀取正常。
4. 不同角色只能使用授權範圍內的功能。
5. AI 回覆應檢查正確性、穩定性及錯誤處理。
6. 發現問題應記錄並修正，修正後重新測試。
7. 測試資料與正式使用者資料必須分開管理。

## 三、測試項目規劃

### 3.1 功能測試（Functional Testing）

確認各項功能是否符合需求。

預計測試項目：

- 使用者註冊、登入及登出
- 忘記密碼及密碼重設
- 學生與教師角色權限
- 課程及教材瀏覽
- 題庫練習與模擬測驗
- 作答、計分及成績紀錄
- 學習進度及錯題紀錄
- 遊戲及獎勵系統
- 教師管理功能
- AI 學習輔助功能

### 3.2 介面與操作測試（UI/UX Testing）

確認不同裝置及螢幕尺寸下的使用體驗。

測試範圍：

- 電腦版網站
- 平板版網站
- 手機版網站
- 按鈕及導覽操作
- 表單輸入及錯誤提示
- 頁面載入與切換
- 動畫及互動效果
- 文字、圖片及版面顯示

### 3.3 系統整合測試（Integration Testing）

確認不同系統模組之間能正常合作。

測試範圍：

- 前端與後端資料傳輸
- 後端與資料庫連線
- 登入狀態與角色權限
- 題庫、測驗與成績資料整合
- AI 服務與學習功能整合
- 教師管理與學生資料整合

### 3.4 API 測試

確認系統 API 能正確接收及回傳資料。

測試範圍：

- API 請求格式
- 回應資料格式
- 錯誤代碼及錯誤訊息
- 未登入時的存取限制
- 未授權角色的存取限制
- 異常輸入及缺少欄位的處理

### 3.5 資料庫測試（Database Testing）

確認資料能正確建立、讀取、修改及刪除。

測試範圍：

- 使用者資料
- 課程及教材資料
- 題目與答案資料
- 測驗及作答紀錄
- 學習進度
- 遊戲及獎勵紀錄
- 教師與班級管理資料

### 3.6 AI 功能測試（AI Testing）

確認 AI 輔助學習功能能正常運作。

測試範圍：

- 題目內容理解
- 答案與解題說明
- 分階段提示
- 錯誤原因分析
- 學習建議
- AI 無法回答時的處理
- API 連線失敗時的提示
- 回覆內容是否符合題目及教材

AI 回覆應以教材、題目及可靠資料為依據，並保留使用者自行思考與作答的空間。

### 3.7 安全性與權限測試（Security Testing）

確認系統及使用者資料受到適當保護。

測試範圍：

- 密碼安全儲存
- 登入驗證
- 使用者角色權限
- 未授權資料存取
- API 存取安全
- 輸入資料驗證
- 敏感資料保護
- 登入及操作異常處理

## 四、測試環境管理

測試環境應與正式環境分開，避免測試操作影響正式資料。

| 環境 | 用途 |
| --- | --- |
| 開發環境 | 開發人員撰寫及初步測試 |
| 測試環境 | 整合功能及驗證系統 |
| 正式環境 | 提供正式使用者使用 |

測試時應使用測試帳號及測試資料，不應直接使用真實使用者的個人資料。

## 五、問題回報與修正流程

發現問題時，依照以下流程處理：

1. 記錄問題發生的位置。
2. 描述操作步驟及預期結果。
3. 記錄實際發生的結果。
4. 提供必要的錯誤訊息或畫面截圖。
5. 指派負責成員進行修正。
6. 修正完成後重新測試。
7. 確認問題排除後更新紀錄。

## 六、測試紀錄格式

每項測試應保留基本紀錄：

| 欄位 | 說明 |
| --- | --- |
| 測試編號 | 每項測試的識別編號 |
| 測試項目 | 本次測試的功能 |
| 測試步驟 | 實際操作流程 |
| 預期結果 | 正常情況下應出現的結果 |
| 實際結果 | 測試後觀察到的結果 |
| 測試狀態 | 通過、失敗或待處理 |
| 負責人 | 執行或修正人員 |
| 備註 | 錯誤原因及其他說明 |

## 七、測試完成標準

功能符合以下條件，才能視為完成：

- 主要操作流程能正常執行。
- 資料新增、讀取及更新結果正確。
- 權限限制符合角色設定。
- 異常操作有適當提示。
- 不影響其他既有功能。
- 相關測試紀錄已更新。
- 發現的重大問題已完成修正。
