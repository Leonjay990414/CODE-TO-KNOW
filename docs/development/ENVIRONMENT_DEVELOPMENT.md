## 1. 開發環境目標

本專案採用兩人協作開發模式。

兩位成員應具備可獨立執行專案的本機開發環境，並透過 GitHub 管理程式碼及版本。

開發環境必須符合：

1. 能夠正常編輯及執行專案。
2. 能夠安裝及管理專案套件。
3. 能夠使用 Git 進行版本管理。
4. 能夠連接 GitHub Repository。
5. 能夠安全管理環境變數及 API 金鑰。
6. 能夠在本機測試網站功能。
7. 能夠支援未來前端、後端、資料庫及 AI 功能開發。

## 4. 本機開發操作

開始開發前，應先確認：

1. Antigravity 可以正常開啟。
2. 專案資料夾可以正常讀取。
3. Git 可以正常執行。
4. 本機程式碼已與遠端版本同步。
5. 所需套件已正確安裝。

常用 Git 指令：

```powershell
git status
git pull
git add .
git commit -m "feat: describe your changes"
git push
```

注意：

- `git pull` 前應確認本機是否有尚未提交的修改。
- 不可在未確認修改內容時直接使用 `git add .`。
- 每次提交應有清楚的 Commit 訊息。
- 不應將尚未測試的重大修改直接合併至 main。

## 5. 環境變數與機密資料

未來專案可能需要：

- AI API 金鑰
- 資料庫連線資訊
- Email 服務設定
- Google OAuth 憑證
- 其他第三方服務金鑰

管理原則：

1. 機密資料不得直接寫入公開程式碼。
2. 不得將 `.env` 提交至 GitHub。
3. 每位成員應使用自己的本機環境設定。
4. 正式環境的機密資料應由正式部署平台安全管理。
5. `.env.example` 僅提供變數名稱及範例，不放入真實金鑰。

## 6. 開發環境與其他環境區分

本機開發環境只供開發者使用。

未來應區分：

- Development：本機開發。
- Testing：功能測試與整合測試。
- Production：正式服務及真實使用者。

三種環境的資料、憑證及設定應分開管理，不得任意共用正式資料庫或正式金鑰。

## 7. 兩人協作規範

兩位成員應：

1. 使用各自的 GitHub 帳號。
2. 透過 Repository 權限進行協作。
3. 開發新功能時使用功能分支。
4. 完成後進行測試與程式碼檢查。
5. 確認無重大問題後再合併。
6. 定期同步專案版本。
7. 不共用個人帳號密碼或私人憑證。

## 8. 開發環境安全規範

- 不隨意執行來源不明的安裝指令。
- 不將 API 金鑰貼入公開對話或程式碼。
- 不提交個人操作紀錄及敏感設定。
- 安裝套件前確認套件名稱與來源。
- 定期檢查套件安全性及相依版本。
- 重要修改前先確認 Git 工作目錄狀態。
