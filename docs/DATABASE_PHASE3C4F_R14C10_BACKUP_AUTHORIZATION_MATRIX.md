## 一、失敗處理與強制中止條件 (Hard Abort Triggers)

為杜絕任何不完整、損毀或未經驗證的備份被誤認為有效基准，凡在正式備份執行流程中觸發下列**任一中止條件**，必須**立即中斷流程（HARD ABORT）**，並嚴禁進入後續角色建立或權限調整階段：

| 中止代碼 | 觸發條件說明 | 偵測機制與依據 | 處置方式 | 驗證層級標記 |
| :--- | :--- | :--- | :--- | :--- |
| **ABORT-01** | **磁碟可用空間不足 (< 10 GB)** | 備份前透過 OS 檢測磁碟剩餘空間 | 立即拒絕啟動，防止磁碟滿載中斷 | 【已由原始碼確認】 |
| **ABORT-02** | **Root CA 憑證遺失或指紋不符** | SHA-256 非 `70072358...F3B7` | 拋錯退出，拒絕建立不安全連線 | 【已由原始碼確認】 |
| **ABORT-03** | **Supabase 端點連線失敗或超時** | Docker 容器連線拋出非 0 狀態碼 | 記錄診斷輸出，不留暫存檔退出 | 【已由原始碼確認】 |
| **ABORT-04** | **`pg_dump` 執行非正常結束** | `ExitCode != 0` 或 `Length == 0` | 刪除未完成之暫存 dump 與目錄 | 【已由原始碼確認】 |
| **ABORT-05** | **AES-256-GCM 加密或標籤寫入失敗** | pipeline 拋錯或未取得 Auth Tag | 刪除 `.tmp` 暫存，絕不留無效密文 | 【已由本機測試證實】 |
| **ABORT-06** | **SHA-256 數位指紋比對不一致** | 明文或密文與記錄值相差 1 bit | 標記備份損毀，立即阻斷後續流程 | 【已由本機測試證實】 |
| **ABORT-07** | **GCM 解密認證失敗 (位元篡改/偽冒)** | Decipher final 拋出認證錯誤 | 立即清除解密暫存，阻斷還原程序 | 【已由本機測試證實】 |
| **ABORT-08** | **PG17 沙盒還原失敗或物件數 < 37** | 表計數不等於 37 或 Enum 遺失 | 判定備份無效，通報專案負責人 | 【已由本機測試證實】 |
| **ABORT-09** | **加密主金鑰遺失或未妥善保存** | 負責人無法確認密碼庫保管狀態 | 嚴禁進入正式資料庫異動階段 | 【僅為規劃】 |
